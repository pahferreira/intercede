# Neon Postgres with pgvector, outside AWS

Intentions, their embeddings, and the fairness counters live in one Postgres database on Neon's free tier with pgvector, accessed through Drizzle and postgres.js over Neon's pooled connection string. The ranking question ("similar to this Entry, favouring Intentions with few Commitments and not yet seen by this Visitor") is a single relational query here, while an all-AWS setup would split it across two stores and move ranking into application code. RDS was ruled out because it costs at least about $15/month once credits run out.

## Considered Options

- **DynamoDB + S3 Vectors**: all AWS and pay-per-use, but two stores to keep consistent.
- **DynamoDB + in-memory cosine**: works for a few thousand rows and teaches nothing reusable.

## Consequences

- Postgres major version is 18 (Neon's default for new projects since June 2026). Local development uses a `pgvector/pgvector` Docker image on the same major, and the Neon project must match it.
- Migrations are SQL files generated by drizzle-kit and applied by the pipeline. A change with no schema diff (such as enabling an extension) is a custom migration (`drizzle-kit generate --custom`).
- One schema per context plus `platform`. IDs are UUIDv7 generated in the domain.
- Data access sits behind repository ports, so a move to another store means writing a new adapter.
